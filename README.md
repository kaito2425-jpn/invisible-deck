# Invisible Deck App

スマートフォン向け Invisible Deck（古典マジック）アプリ。バニラJS（HTML/CSS/JS）の3ファイル構成。

## 構成

```
/
├── index.html
├── style.css
├── app.js
├── assets/
│   ├── cards-sheet.svg   # 52枚スプライト（13列×4行）
│   └── card-back.png     # 黒×ゴールド和風麻の葉の裏面
└── README.md
```

## 開発フェーズ

- **Phase 1（完了）**: State機械の骨格、13ホットスポット、観客モード。裏返しは `FLIP (tap)` ボタン（デバッグ時のみ表示）またはカード長押し（700ms）で代替。
- **Phase 2（完了）**: 52枚の SVG カード組み込み、スライド/めくれアニメ、履歴回避ランダム。
- **Phase 3（実装済み・実機テスト待ち）**: DeviceOrientation API（β角で裏返し検知、0.5秒デバウンス）、iOS Safari 許可ダイアログ（初回タッチ時に要求）、30秒自動リセット、デバッグHUDにβ角表示。

## Phase 3 実機テスト手順（iPhone Safari）

1. `https://invisible-deck.vercel.app/?debug=1` を開く
2. 画面をどこか一度タップ →「動作と方向へのアクセス」ダイアログ →**許可**
3. HUD の `flip / β` 行が `(on)` になり、端末を傾けるとβ角が動くことを確認
4. スマホを表向きに平らに持つ（β≈0°）→ 奥へクルッと裏返して画面を下に向け0.5秒静止（|β|>160°）→ `BACK_SHUFFLE`（裏面表示）になる
5. 表に戻して0.5秒静止 → `READY_TO_ENCODE`（ランダムな10のカード）になる
6. 手に持って普通に見せる角度（β≈45〜90°）では誤発動しないことを確認
7. 許可を**拒否**した場合：長押し（700ms）で代替可能なこと、および再許可には Safari を完全に終了して再訪問（または「ぁあ」→ Webサイトの設定）が必要なことを確認

**本番運用の注意**: 演技前に必ず一度、自分で画面をタップして許可を済ませておくこと（観客に配ってから初回タッチが起きると、観客の目の前に許可ダイアログが出てしまう）。

## デバッグモード

URL に `?debug=1` を付与すると有効化:

- 13ホットスポットの半透明オーバーレイ（番号付き）
- 現在の State / encodedCard / インデックス表示
- スワイプ方向ログ（コンソール + HUD）
- `FLIP (tap)` ボタン表示

## Phase 1 動作確認手順

1. `?debug=1` で起動 → `INITIAL_SHUFFLE`、ランダムカード1枚
2. 左→右スワイプ：別のランダムカードに切り替わる
3. `FLIP` ボタン or カード長押し：`BACK_SHUFFLE`（裏面表示）
4. もう一度 `FLIP`：`READY_TO_ENCODE`、ランダムな10カード表示
5. 13ホットスポット領域を押して方向スワイプ：`ENCODED`（見た目変化なし）、HUDに `encoded` が出る
6. ホットスポット外で左→右スワイプ：`AUDIENCE_SWIPING`、カードが流れる
7. 7〜13枚目のどこかで裏向きカードが出現
8. 裏向きカードをタップ：めくれ演出 → 仕込んだカードが表示 → `FINISHED`
